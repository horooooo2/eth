# 区间回归策略 V3：周度选向、日内分档、单向持仓

版本：`weekly-daily-ladder-v3.0`。这是当前策略页面使用的本地回放规则，替代 V2 衰竭确认引擎。V2 源码及测试已归档为 `event-v2-before-daily-ladder-v3.zip`，未继续叠加在当前执行逻辑中。V1/V2 旧报告保留原版本，可继续导出；历史 CSV 可以复用，但旧版本参数不会被当作 V3 参数自动恢复。

## 方向与价格口径

- UTC 零点切日。周度涨跌 = 此前七根完整日线最后收盘 / 第一根开盘 − 1，使用滚动七日，不是自然周。
- 默认周度阈值 1%：达到负阈值只考虑做多，达到正阈值只考虑做空，其他情况空仓。方向在当天固定，不让当天最终收盘参与事先判断。
- 日内档位依据当天开盘价，默认绝对涨跌幅 5%、10%、20%。它们不是最高最低之间的振幅，也不是七日累计跌幅。
- 当日开始时即可依据开盘和已完成七日背景安排限价档位。每根分钟线顺序处理，不预读取未来日线。开头不足完整一天的数据不计入周背景，七根完整日线不足则不挂单。
- 只维护一个持仓。没有双向同时开仓，没有 V2 的小时冲击、5分钟衰竭确认或1.2收益风险比门槛。

## 建仓与补仓

- 三个档位默认累计比例 10%、30%、60%，均可在界面修改，必须递增。比例同时用于累计保证金额度和累计计划风险额度，以免第一档就耗尽全部止损预算。
- 例如事件保证金预算1,000U时，三个累计保证金上限是100/300/600U；第二档只允许补到累计300U，不另加300U。实际投入还受风险预算、可用权益和数量步进限制，可能小于保证金上限。剩余40%不自动动用。
- 每个事件的每档最多成交一次。若某档因为预算内数量不足而未成交，更深档仍可检查；不会因为价格反复穿越同一档而不断追加。
- 同一分钟跨越多个档位，按浅到深的保守不利路径模拟，使用各档限价和累计余额，不将10%+30%+60%全额相加。不给跳空买单自动改善到更便宜开盘价，也不凭最低价触碰就认定成交：须穿过限价至少1 Tick。
- UTC换日撤销未成交挂单，用新日开盘重算价格。已有事件的总预算、首次参考止损、已成交最高档、首次开仓时间不重置。只安排比已成交档更深、比当前均价更有利、且仍在原止损内的档位。
- 换日发现周度方向反转或中性，暂停补仓，继续按原仓位管理退出，不自动反手。
- 平仓后取消全部剩余挂单，当天不重建；下一个UTC日重新选择方向和评估事件。

## 风险与退出默认值

- 模拟账户40,000U，事件保证金预算1,000U，杠杆3×。
- 事件计划风险上限100U，同时不超过事件建立时已实现权益的1%。预算在事件建立时冻结，不能因为换日、补仓或浮盈上调。
- 初始参考日开盘向不利方向30%为固定止损，必须比最高日内档位更深；不是每次补仓后再给30%的空间。每次入场计划风险包含到止损的价格损失、全部入场费、预计退出费及滑点；已发生的负资金费也占用剩余额度，正资金费不扩张新增风险额度。
- 若止损距离达到入场价的 `0.8 / 杠杆`，放弃该档。这只是保守的杠杆距离限制，不是交易所清算模型。
- 整体净止盈默认累计入场名义本金的1%，不是保证金收益率。目标价覆盖全部入场费用、预计退出费用、滑点和已结算资金费；补仓后按整体加权均价重算。
- 最长持仓默认24小时，可设1–168小时。从第一次成交开始，补仓不重新计时。
- 入场Maker费默认0.02%；退出Taker费0.05%、不利滑点0.05%。这些是可修改的研究参数，非官方账户费率保证。数量向下取步进，不能为强行成交向上超预算。
- 已持仓开盘跳空越过止损时先退出，不在失效价格继续补仓。分钟内多档和止损同时穿越时，先按不利路径补仓再止损；有新增成交的分钟不假设先买后反弹止盈。无新增成交时，止损优先于同分钟止盈。
- 价格跳空、持续资金费和实际流动性仍可能让损失超过计划预算。没有订单队列、滑点冲击或维持保证金/标记价清算模拟，不是实盘可执行收益保证。

## 数据和页面

- 资金费在时间戳先向原有仓位结算，再处理同分钟开平仓。正费率多付空收；优先用文件的标记价，没有则以该分钟开盘价代理。
- 权益和最大回撤按每分钟收盘计算，包含已实现/浮动净盈亏，手续费与资金费不重复扣除。数据末尾未平仓保留浮盈，不虚构将来的止盈。
- 页面提供周度阈值、三档日涨跌与累计比例、事件预算、止损、净止盈、最长持仓、费用参数；显示周度方向、日开盘、当日涨跌、开仓/补仓/过滤/撤单统计及每档明细。
- 完成回放的JSON包含所有事件和所有平仓及其分档成交；运行途中报告标明事件明细不完整，只带最近20个事件。界面列表也仅显示最近20个事件以控制开销。
- AI仍为独立实时旁路，不参与方向、入场、补仓或退出。虚拟币/雷达模块和服务器采集逻辑未因本次策略替换而改变。

## 验证

`npm --prefix whale-tracker-frontend run test:strategy`：完整/不完整日线、周度上涨/下跌/中性、日开盘基准、单向持仓、累计额度、同档不重复、跨日预算与时钟、换日撤单、方向反转冻结、多档穿越与止损、资金费时序/符号/标记价、费用和止盈取整、时间止损、同日不重建、实际Worker未来数据前缀一致性。

`node whale-tracker-frontend/scripts/test-replay-csv.cjs`：CSV时间、OHLC、重复/缺失行及资金费完整性。

年度集成检查使用本地BTCUSDT文件2025-10-05至2026-10-04：525,600根分钟线，1,095条非零资金费记录。默认参数产生302个观察事件，2次多头开仓并退出，0次补仓，19次预算/步进过滤，净盈亏约+2.0744U，逐分钟收盘最大回撤约1.2496U。这个样本的两笔交易不能证明策略盈利；多空与补仓分支另由合成路径验证，未为了增加成交调参。

文件从10月5日开始，因此10月10日没有此前七根完整日线，不能用于验证那天是否应成交。多数浅档在BTC价格下受预算和0.001数量步进限制而跳过，界面/报告保留具体原因。

复现：`node whale-tracker-frontend/scripts/run-daily-ladder.cjs <分钟CSV> <报告JSON>`。该脚本使用生产解析器/引擎与上述默认参数；报告含数据SHA256，当前结果保存在 `daily-ladder-v3-btc-verification.json`。`BTCUSDT_daily_ladder_SYNTHETIC.csv` 仅用于浏览器界面验证，不是市场历史数据。
