# TradFi 情绪策略与回放实现记录

> 状态：策略研究、观察入口和回放功能已按用户要求移除。本文仅作项目记忆，不代表当前仍提供这些功能。
> 更新：2026-09-30

## 当前 TradFi 页面

TradFi 是传统金融市场观察页面，不负责账户、仓位、下单或策略管理。页面内容为：

- TradFi 自选标的和实时行情摘要。
- 当前标的价格、24 小时涨跌、合约类别与行情状态。
- 传统金融分析线索：贵金属的利率/美元/ETF/供需，股票的财务和经营字段，ETF 的成分与宏观字段；关注事件。
- 关联标的新闻、分类、搜索、来源和更新时间。

新加的“情绪过冲策略”按钮、策略观察弹窗、策略回放路由和回放页面已移除。页面不再显示交易账户、成交记录、挂单、持仓或平仓入口。TradFi 原有行情、资讯及市场数据 API 保留。

## 研究策略原意

研究目标是捕捉统计异常行情后的衰竭回归，不把“涨多了/跌多了”直接当反转信号：

1. 检测异常上涨或下跌，记录事件前 ATR 基准。
2. 异常只进入观察；创新高/低时沿用同一事件及风险预算。
3. 方向性事件先出现至少 `0.5 × ATR_pre` 的回撤，再观察反弹/反抽失败及结构破坏。
4. 结构信号在下一根可成交时刻执行；单事件至多一次，不加仓、不重新入场。
5. Maker 极端挂单作为对照组；A_K3 至 A_K6 对比固定标准差，B 是衰竭确认。测试场景含 Maker 同根止盈敏感性。
6. 止损、时间退出、缺口未知、成交费用和滑点进入账本。保留连续账户路径、事件收益、交易收益、尾部 MAE/扩展和日聚类区间等指标；全样本结果在回放时间轴结束前不能暴露。

策略不是盈利承诺。最初希望检验的问题是：衰竭确认在扣除成本后能否改善每事件收益及尾部风险，相比提前在极端位置逆势挂单是否更可靠。

## 回放输入和参数记录

原回放读取单标的 CSV/Parquet，支持 1m 与 5m；1m 只将完整五根聚成 5m，不填补数据缺口。UTC、秒/毫秒/微秒/纳秒时间戳可导入。用户提供的 XAU 示例同时有 `open_time_utc`、`open_time_bjt`、`open_time_ms`；实现曾把三列误判为重复，修复后会比较它们表示的 UTC 瞬间，一致才接受。

用户给出的回放默认费用/风险配置：

| 字段 | 默认值 |
| --- | ---: |
| 每事件风险预算 | 100 USDT |
| Maker 手续费 | 2 bps |
| Taker 手续费 | 5 bps |
| 计划入场滑点（保留字段） | 0 bps |
| 计划止损滑点 | 5 bps |
| 实际入场滑点 | 2 bps |
| 实际退出滑点 | 5 bps |

曾以 Binance XAUUSDT 规则预填精度：tickSize `0.01`，stepSize `0.001`，minQty `0.001`，最小名义金额 `5 USDT`。真实标的规则可能变更；策略研究应以目标数据/交易所规则重新核对。

原实现取消了前后端 32MB 和 600,000 行上限，但大文件仍受内存、HTTP 部署代理、解析器、存储和计算时间约束，并非实际无限容量。

## 曾实现过的工程模块

- `emotion_backtest/`：Python 规范策略、事件状态机、模拟执行、指标、报告和研究 CLI；A/B 组共享同一基准。历史人工路径、执行、指标、导入和 Node/Python 一致性测试。
- 后端 `tradfiEmotionCore.cjs`：实时可观察状态逻辑；`tradfiEmotionStrategy.js`：仅观察公开市场行情，不发送签名交易 API 请求。
- 后端 `tradfiEmotionReplay.js` 和 `routes/tradfiEmotionReplay.js`：认证的回放任务桥接，委托 Python 规范引擎，校验任务所有权及风险、成本、精度字段。
- 前端 `TradFiReplay.vue`：导入文件、填写成本/风险/精度，查看 A/B 回放时间轴、事件明细、统计、导出 JSON，并将选择的数据保存到浏览器 IndexedDB。
- 服务曾限制每用户一个、全服务两个并行任务；运行超时 15 分钟，结果约 30 分钟清理。服务重启会丢失内存任务索引。
- 旧网格策略曾切换为退役/排空模式：禁止新启动和补仓，取消旧入场单，保留旧仓位关闭/对账路径，避免遗留持仓失去管理。

本次移除了前后端策略观察入口、回放接口与页面；Python 离线研究目录因其中混有原始规格、历史结果和研究资料而保留在工作区，当前应用没有启动器或 HTTP 路由连接它。上述条目用于说明曾经的实现，不是当前 API 合约。若未来重做，应先从已确认的 Frozen v1.0/v1.0.1 规格和实现澄清重新评审，再恢复隔离的离线研究模块，不要把它挂到传统金融资讯页面或交易账户 UI。

## Binance / OKX API 规则记忆与网站功能状态

### 旧实现中的凭证与环境规则

以下记录来自项目当时的实现（`userExchangeKeys.js`、`binanceTradfiTrade.js`、`okxTradeClient.js` 和交易路由），仅供维护旧代码时参考。网站已移除交易所 API 设置与所有订单操作入口；这些规则不表示当前网站仍可连接交易所。

- OKX 私有 API 凭证必须包含 API Key、Secret、Passphrase，数据库行还需启用；请求签名为 HMAC-SHA256 后 Base64 编码，签名原文为 `timestamp + 大写 HTTP method + requestPath + body`。认证头为 `OK-ACCESS-KEY`、`OK-ACCESS-SIGN`、`OK-ACCESS-TIMESTAMP`、`OK-ACCESS-PASSPHRASE`。模拟交易通过 `x-simulated-trading: 1` 标记；关闭模拟模式时不发送该标记。模拟盘和实盘应使用各自环境对应的 API 凭证。
- Binance 私有 API 凭证必须包含 API Key、Secret，且凭证行需启用。项目期货客户端为参数增加 `timestamp` 与 `recvWindow=5000`，对 URL 编码参数串做 HMAC-SHA256 十六进制签名，并使用 `X-MBX-APIKEY` 请求头。模拟盘基址为 `https://demo-fapi.binance.com`，实盘为 `https://fapi.binance.com`。旧设置逻辑不允许只切换 Binance 模拟标记而复用原密钥；如需切换环境，应同时换成该环境签发的密钥。
- 旧凭证表以 SQLite 字段 `api_key`、`api_secret`、`api_passphrase` 保存原值；返回给界面的元数据只提供掩码 Key 和是否已存 Secret 等标记。这里记录的是现存实现的事实，不是建议的安全设计。禁止在日志、错误详情或 API 响应中输出完整 Secret/Passphrase；未来若重新接入，应采用加密静态存储、最小权限且禁用提现权限的密钥，并先检查签名、环境切换和脱敏。
- 移除交易 UI 和路由不会自动删除 SQLite 中已有的凭证，也不会在交易所撤销密钥。若这些旧密钥不再需要，用户应自行到 Binance/OKX 控制台撤销；不要把密钥复制到聊天或普通 Markdown。本文只记录规则，不记录任何真实密钥。

### 当前网站边界

- 已从侧栏/设置入口移除 Binance 和 OKX API 密钥配置，AI 设置只管理 DeepSeek 密钥。
- AI 市场简报、技术/资讯/情绪分析以及只读方向观点保留。观点中的参考入场、止损和止盈仅用于分析展示，不会被网站提交为交易订单。
- 已从应用路由移除 `/okx/trade`、`/okx/keys`；TradFi 路由仅保留 `/catalog`、`/quotes`、`/intel`、`/whales` 和 `/whales/all` 只读市场数据，账户、策略启停、补仓、同步和一键平仓路由已移除。
- 旧网格服务的排空/遗留仓位管理逻辑仍留在后台启动路径中，用于维护可能存在的旧仓位；它不是网站上的新开仓功能。若部署实例仍有旧仓位或挂单，应先在交易所核对并妥善处理，再决定是否彻底删除这段兼容代码。

## 验收记录（移除前）

- Python 策略/导入测试曾通过 36 项，包括时间戳多列一致性回归。
- Node 回放权限与成本校验、前端类型检查/构建、播放时间轴边界测试曾通过。
- 人工合成数据端到端计算曾生成 26,244 根 K 线、1 个异常事件及 9 个策略/执行场景结果。
- XAU 用户 CSV 曾成功读入 380,160 行，生成 76,032 根 5m 数据，无不完整聚合桶。

这些结果验证的是程序的可运行性和因果边界，不是策略真实市场的统计优势。
