# 巨鲸观察 v1 — 实施与运行说明

日期：2026-10-06。范围：虚拟币页面左侧使用「巨鲸观察 / 宏观数据」Tab，中间保留巨鲸列表，右侧独立显示异动记录。没有外部发帖、AI 自动调用或下单行为。

## 数据路径

既有服务端采集 → 原始成交事务内写入 observation_inputs 和 observation_jobs → 后台任务按地址/合约生成摘要 → SQLite 保存摘要与证据 → 同源 HTTP 首次加载 → 既有 /realtime 连接推送 observationCommit。

前端不请求外部交易数据；刷新按钮只读服务器已算好的快照。采集任务不依赖网页打开。

## 规则

- 持续建仓：行为段最长 60 分钟，相邻成交间隔不超过 15 分钟，仓位数量可衔接；至少 3 笔原始成交、跨度至少 5 分钟、增仓成交金额至少 50 万美元。期间减仓单列。成交笔数不等于订单数。
- 反手：一笔跨零成交，或相邻可确认的平仓和反向开仓间隔不超过 30 分钟。新方向开仓至少 50 万美元。多笔情况只描述「已采集到平仓后反向开仓」，不保证中间没有其他未采集交易。
- 显著减仓：连续减仓段的净数量减少至少 30%，减仓成交至少 50 万美元。以数量计算，绝不使用美元仓位价值变化代替。先加仓后减仓也可单独识别。
- 缺失起始仓位、不能分类的成交作为连续性断点；不能可靠排序的同时间成交不计算多笔减仓比例。
- 明确的 liquidation / ADL 不描述为主动建仓或撤退。
- 金额由实际成交价乘数量累计。反转交易分腿，但证据仍保留一笔成交，已实现盈亏不复制到开仓腿。
- 所有内容均为已采集事实。没有市场方向预测、完整账户净收益、交易动机推测。

- lib/whaleObservationStore.js：原始输入副本、事务任务、摘要和证据存储；同一成交修订覆盖旧贡献。
- lib/whaleObservationWorker.js：已有 fills 分批初始化、任务恢复、分批处理及实时推送。
- lib/db.js：新增 4 张表与索引。
- lib/sqliteStore.js：实时与批量两条成交写入路径均在原事务内登记新模块输入。
- routes/whales.js：只读快照与依据接口。
- lib/realtimeHub.js：新连接发送观察快照，复用既有连接。
- src/components/WhaleObservationPanel.vue：过滤、阅读更新提示、证据展开、定位和详情入口。
- src/utils/whaleObservationState.ts：增量合并与序号连续性检查。
- scripts/sync-deploy.js：包含上述运行文件，并补齐原先遗漏的 directionSummary.js。

## 存储及负载

- observation_inputs：精简原始事实副本，唯一键使用项目统一 canonicalTradeId。
- observation_jobs：地址/合约去重的持久任务，与原始成交在同一事务登记，处理成功后删除。
- whale_observations：仅摘要，含规则版本、修订号、首次发布时间、最后修订时间与事件时间。
- observation_evidence：按事件保存证据，列表查询不解析该大字段。
- 输入、摘要和证据保留 7 天；前端展示最近 24 小时的最近 100 条，币种和类型筛选在这 100 条内。证据每次返回 50 笔。
- 保留输入会增加磁盘占用，需以线上真实成交量观测；不是零成本缓存。暂不自动修改旧模块保留规则。
- 后台每批最多处理 4 个地址/合约，完成一个后检查约 50ms 软预算（无法中断单个计算）。有积压时约 250ms 调度，空闲时 2 秒。单个地址/合约目前重算其保留期输入，极高成交量时还需监测耗时。
- 首次启动每批扫描 1000 条本地 fills，完成后记录初始化标记；不发外部补采请求。首批整理完后才开始生成事件，避免把半批历史当成完整行为。服务器重启不重复全量初始化，但继续处理未完成任务。
- 使用 WHALE_OBSERVATIONS_ENABLED=0 可停止后台生成；原始成交事务记录仍保留，恢复后可继续处理。

## 协议

GET /api/whales/observations：内存中的最近摘要快照，epoch/seq/error/warming。asOf 是响应时间，不是上游采集时间；卡片使用 startAt/lastAt。

GET /api/whales/observations/:id/evidence?offset=0：最多 50 笔依据，附摘要 revision；记录撤回返回 404。

Socket 新连接直接发送 observationSnapshot。之后发送 observationCommit，仅含变化的摘要与当前完整有序 ID 列表；ID 列表之外的摘要从前端状态移除。epoch 改变、序号缺口、缺失依赖记录则重取观察快照，不刷新巨鲸列表。HTTP 恢复有水位检查，防止恢复期间的新消息丢失。

没有声音或弹窗通知；阅读中不强制滚动，显示「观察记录有更新」。历史补录同样更新事实，但不标为刚刚成交。事件时间从不替换成接收时间。

## 当前边界

- 只做三类单地址合约行为；跨事件后续、多地址集中行动、链上转账和地址归属不在 v1。
- 卡片不拼接可能滞后的当前仓位快照；通过「巨鲸详情」查看现有仓位，避免把历史行为与当前仓位误作同一时刻。
- 首版 50 万美元阈值固定在 POLICY，并未证明是最佳阈值。没有前端改规则的管理入口。
- 连续性表示观测到的数量能够衔接，不表示官方历史全覆盖。
- 首次上线可用历史取决于旧 fills 的实际保留范围；不会凭空恢复已删除数据。

## 验证

独立 SQLite 测试覆盖去重、乱序、开/平方向、跨零反手、未知成交断点、先开后减、盈亏归属、事务回滚、修订撤回、证据独立存储。

前端状态测试覆盖重复推送、序号缺口、epoch 变化、撤回、缺失 ID。

同时回归现有 direction summary、resonance、state stream、state commits、whale sync integration；执行 Vue 类型检查与生产构建。

部署：后端需要重启以建表并启动后台任务；前端发布新构建。无需新的密钥或外部 API 配置。测试结果不替代上线后的采集延迟和磁盘增长监测。
